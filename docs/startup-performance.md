# 启动性能优化（2026-09-15）

在当前 0.1.43 工作区基础上优化会话恢复和富文本导入。未改动数据库完整性校验、恢复日志和保存确认流程。

## 实测结果

同一台 Windows 电脑、Electron 40.10.6、生产构建，每个场景分别启动三次，取中位数。计时从 Playwright 发起 Electron 启动开始，到已保存的活动标签编辑器可编辑为止，包含自动化连接开销。

| 场景 | 优化前 | 优化后 | 耗时减少 |
| --- | ---: | ---: | ---: |
| 单文件，5,000 个事件 | 1,824 ms | 1,214 ms | 33.4% |
| 恢复 4 个文件，每个 1,500 个事件 | 2,208 ms | 914 ms | 58.6% |

四文件场景启动时的编辑器实例由 4 个降为 1 个。每次启动使用独立测试配置，关闭提醒，活动标签固定为最后一个文件。样本为普通文本段落；使用 `TODOLINE_TEST=1` 的隐藏窗口，未清空操作系统文件缓存。这是重复启动的相对比较，不代表打包 EXE 的冷启动时间，也不能直接外推到大量图片或复杂表格的文档。

原始三次采样保存在 [startup-performance-2026-09-15.json](startup-performance-2026-09-15.json)。其中 `paintedMs` 是编辑器出现后再等待两次 `requestAnimationFrame` 的总耗时，不是实际屏幕显示时间；内存测量有波动，仅作辅助记录。

## 发现与实施

- 恢复会话原先逐个打开、激活文件，且每个隐藏标签都会创建完整编辑器。现在并发请求文档快照，按原顺序一次恢复标签，只初始化活动标签。首次访问其他标签时再创建编辑器，之后保留实例与撤销历史。
- 编辑器原先在普通 effect 中挂载，文档恢复可能跨越额外的布局周期。现在在布局 effect 中完成活动编辑器初始化与滚动恢复，确保搜索和提醒跳转可以立即定位。
- 每个事件导入 HTML 时都创建空 DOM 文档，5,000 个事件重复创建 5,000 次。现在单次文件导入共用一个空文档，每个事件仍用独立的惰性模板解析，保持样式隔离及不支持格式的原文保护。
- 后台提醒可以按需初始化尚未访问的标签并保存完成状态，不切换当前文件。恢复活动文件改用路径匹配，避免前面的文件丢失后激活错误标签。

后台文件仍读取快照，因此跨文件搜索、提醒和恢复内容可用；首次访问一个大型后台文件仍需承担该文件的编辑器初始化时间。后续若继续优化，可进一步评估活动文件优先读取、非必要面板按需加载和超大文档渲染；本次收益主要来自减少重复解析与隐藏编辑器初始化。

## 复测

```powershell
node scripts/build.mjs
node scripts/benchmark-startup.mjs local-check
```

结果写入 `.cache/startup-benchmark/local-check.json`，夹具与独立配置也位于该目录。脚本不修改用户文档。比较两个版本时，分别构建后使用不同结果名称运行。

## 验证

- 生产构建、TypeScript 类型检查通过。
- 完整单元测试：36 个文件、803 项通过，包括新增的延迟初始化、后台恢复快照保存和共享解析文档隔离测试。
- 新增 4 项启动端到端测试全部通过：延迟初始化与光标/滚动/撤销、缺失文件后的活动标签恢复、跨文件搜索、后台提醒完成与撤销。
- 相关端到端回归覆盖启动命令、标签操作、原文保留与偏好设置：合计 27 项中 25 项通过。其余 2 项是窗口边界的精确像素断言，在当前 150% 缩放屏幕上，已发布 0.1.43 和优化版均复现相同结果：恢复高度从 601 变为 604，工作区宽度 1,707 时窗口宽度为 1,708。本次未调整窗口尺寸逻辑，也未放宽断言。
