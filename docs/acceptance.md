## 架构与格式

主进程负责窗口、文件对话框、剪贴板、资产协议、导出和提醒。`utilityProcess` 中的 better-sqlite3 独占数据库连接；显式 RPC 方法白名单和类型化 preload 不提供任意 SQL、任意文件读取或进程执行接口。渲染器启用沙箱、contextIsolation 和 CSP，不启用 Node 集成。

每个标签只创建一个 ProseMirror 文档和编辑器。正文、分隔线、图片及文档头身份均属于同一个事务与撤销模型。SQLite 分配的 ID 通过别名映射回编辑器，不重写历史。分隔线的额外控制节点在接近视口时补建，正文和选区 DOM 始终保留。侧栏按批次显示导航项，不虚拟化编辑区正文。

文件仍使用 format_version=1 的 events/meta/assets/FTS 表。保留事件顺序、ID、时间戳、deadline、done、top_divider 和资产 BLOB。正文节点未改变时直接保存原 HTML；无法可靠转换的事件只读保护原文。对齐、上下标等未实现格式进入只读回退。

保存采用 500ms 防抖、每标签串行队列、增量 SQL 事务、FULL 同步及成功确认。首次写入前通过 SQLite online backup 保留 WAL 中的已提交数据。`data_version`、文件身份和事务内复查共同拦截外部修改。待写请求先记入独立恢复日志；失败不丢内存编辑，关闭等待队列完成。恢复记录与磁盘冲突时只允许另存，避免覆盖。最后尚未进入队列的 500ms 输入不在强制终止恢复承诺内。

## 5000 事件性能

固定样本由正式 DocumentStore 生成：5000 条事件，每条一段相同结构的中文与数字，无图片。基准脚本会显示窗口；隐藏窗口的 Chromium 绘制节流结果不用于验收。按键计时从 keydown 到下一次 requestAnimationFrame，P95 包含 78 次输入。

| 指标 | 当前测量 | 目标 |
| --- | ---: | ---: |
| 启动到首屏可编辑 | 1452 ms | ≤2000 ms |
| 按键到下一帧 P95 | 20.3 ms | ≤50 ms |
| 搜索“事件 4999” | 1.9 ms | ≤300 ms |
| 全进程工作集合计 | 733.9 MiB | 记录，无硬阈值 |
| 30 次跨文档滚动绘制 | 916 ms | 记录 |

原始数据在 `performance-electron.json`。这是一次固定样本测量，不代表所有图片密集文档，也不是严格清空操作系统文件缓存后的冷启动测试。

Qt 参考工具同样打开该样本：进程内打开到控件显示约 120 ms，搜索约 1.18 ms，工作集约 23.4 MiB，20 个存活事件控件。Qt 参考使用 offscreen 平台和既有核心，**没有包含进程冷启动或完整主窗口**，不能据此直接计算整机启动/内存倍数。Electron 的多进程和完整正文 DOM 带来的内存成本仍显著，保留 Qt 版有实际价值。

## 最终替换前仍需的人工验收

以下项目没有被自动化结果替代：

1. Windows 微软拼音/用户常用输入法的候选窗口、长组合输入、撤销及混排。现有测试覆盖 Chromium IME 协议，不等于实际输入法人工试用。
2. 在不同物理 DPI 显示器之间拖动窗口、从资源管理器拖入图片。已有自动 DPI 和图片 pointer/drop 路径验证。
3. 实际系统休眠/唤醒和托盘气泡点击。调度去重、延迟时钟和恢复挂钩已实现，但未让当前电脑真实休眠。
4. 用户真实大文件长期编辑、图片密集文档和原版快捷键个人习惯的试用确认。

因此当前发布为独立试用版，原程序继续可用；不宣称已经完成上述人工验证或已替换原版。
