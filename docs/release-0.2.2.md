# 0.2.2

- 正文视野内的事件在左侧导航中使用轻度背景高亮，支持多个事件同时显示、长事件分隔线已滚出视野、首个没有分隔线的事件。
- Ctrl+F 保留完整事件导航，不再按查询过滤。匹配项使用金色，正文可见的匹配项使用更强的金色；清除查询或关闭搜索后回到普通可见事件高亮。用户主动开启的“仅看未完成”筛选仍保留。
- 导航会在正文可见范围改变时让对应条目进入视野；手动滚动导航时不会反复拉回。所有事件都可直接滚动访问，替代原先每次“显示更多”100项。
- 长导航列表虚拟渲染，只挂载当前导航窗口与少量预留行。事件位置只在正文变化时重新建立索引，滚动时二分定位并读取可见范围，按 requestAnimationFrame 合并。可见事件集合不变时不触发状态更新；只跟踪活动标签，收起导航时释放观察器。
- ResizeObserver 与图片加载通知覆盖字体、窗口及图片尺寸变化；保存后的临时事件 ID 映射保持同步。

性能验证：模拟百万事件索引时，单次定位读取不到30个边界。180事件 EXE 可见窗口样本，远距离连续滚动高亮耗时约11–17ms，首次约59ms；导航仅渲染31行。该数字仅对应当前测试机器与样本，不是任意文档的固定耗时。隐藏测试窗口的动画帧节流数据未用于可见窗口性能结论。

启动专项优化：空白/纯 Markdown 会话不启动数据库，已有 TDE 提前并行预热；恢复标签不再逐个重写最近文件配置；减少编辑器中间布局，提前确定行号宽度，批量读写行号位置。详见 [启动专项复查](startup-audit-0.2.2.md)。
